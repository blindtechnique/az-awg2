# Заморозка и выпуск

Про порядок, а не про возможности. Этот файл описывает, что происходит с веткой
`beta` между меткой release candidate и выпуском 3.0.0.

## Что заморожено

С тега `v3.0.0-rc.1` ветка закрыта для всего, кроме исправления дефектов.

**Принимается:**

- исправление воспроизводимого дефекта;
- тест, который **краснеет на откате** исправления — иначе не доказано, что он
  меряет именно правку;
- запись в CHANGELOG, называющая цену ошибки, а не только факт правки;
- правка документации, разошедшейся с кодом.

**Не принимается до выпуска:**

- новые флаги, новые команды, новые проверки диагностики;
- переименования и переделка архитектуры;
- изменение формата файлов состояния (`services.env`, `install-state.env`,
  профили обфускации) — оно ломает путь обновления, а проверить его на
  разнообразии живых серверов внутри заморозки нечем;
- всё, после чего клиентам придётся раздать конфиги заново.

Правило спорных случаев: если изменение нельзя закрыть тестом, который краснеет
на откате, оно ждёт выпуска.

## Отложено за выпуск

- **Разделение прав Telegram-бота.** Сегодня он работает от root — как и весь
  установщик. Развести права значит завести список sudoers, доверенного читателя
  и миграцию уже работающих серверов, то есть ровно тот класс изменений, ради
  которого заморозка и вводится.
- **Адресный план.** На каждый сервис отведена одна `/24`, то есть около 250
  клиентов. Расширение затрагивает выдачу адресов, доктор и путь обновления
  разом — не работа для заморозки.

## Как проверить кандидата

Четыре гейта CI воспроизводятся локально. Гонять их надо **до** пуша и **по
всему дереву**, а не по изменённым файлам: два коммита уже ушли в push
красными именно потому, что линтер запускали по своей правке, а CI запускает
его по `git ls-files`.

Переводы строк — проект ломается на CRLF, bash падает на первой же строке:

```bash
git ls-files -z | xargs -0 grep -lI --binary-files=without-match -P '\r$'
```

Ничего не напечатало — гейт пройден.

Статический разбор по всему дереву, планка `warning`, замечаний должно быть ноль:

```bash
mapfile -t files < <(git ls-files '*.sh'); shellcheck -S warning -e SC1090,SC1091 "${files[@]}"
```

Приёмка целиком, а не отдельный набор:

```bash
bash tests/run.sh
```

Если приёмка идёт на Ubuntu 24.04, наборы со стендами в namespace требуют
разрешения — без него они молча пропускают свою главную часть:

```bash
sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0
```

## Как выпускать

1. Прогнать все четыре гейта на том коммите, который станет выпуском.
2. Переименовать запись в CHANGELOG с `3.0.0-rc.1` на `3.0.0` и поставить дату.
3. Тег `v3.0.0` на тот же коммит.

Если за время заморозки что-то исправлялось — очередной кандидат получает
`v3.0.0-rc.2` и так далее; выпуск идёт с последнего кандидата.

## Общий код с awg3

`regen-all`, диагностика, бэкап и восстановление живут в обоих репозиториях
([awg3](https://github.com/blindtechnique/awg3) и этот). Исправление в общем
коде обязано попасть в оба и в обоих закрыться тестом — расхождение между ними
не ловится ни одним гейтом.
